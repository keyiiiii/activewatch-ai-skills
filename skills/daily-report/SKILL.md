ActivityWatch API を使って、今日の作業日報を自動生成してください。

## 環境情報の取得

1. ActivityWatch API のベースURL: `http://localhost:5600/api/0/`
2. まず `buckets/` エンドポイントからバケット一覧を取得し、`aw-watcher-window` と `aw-watcher-afk` で始まるバケット名を動的に特定する
3. 現在時刻から今日の日付（JST: +09:00）を特定する

## データ取得

- ウィンドウアクティビティ: `buckets/<window-bucket>/events?start=<today>T00:00:00%2B09:00&end=<today>T23:59:59%2B09:00&limit=-1`
- AFK データ: `buckets/<afk-bucket>/events?start=<today>T00:00:00%2B09:00&end=<today>T23:59:59%2B09:00&limit=-1`

※ API の URL は末尾に `/` が必要な場合があるので注意

## ActivityWatch データの特性（重要）

ActivityWatch は数秒間隔でアクティブウィンドウをポーリングし、ウィンドウが変わるたびにイベントを記録する。このため以下の特性を理解して分析すること:

- **1イベント ≠ 1アクション**: 同じウィンドウを開いたまま作業していても、タイトルの微変化（通知バッジの増減、🔊アイコンの付け外し等）で複数のイベントが生成される
- **イベント数は「アクセス回数」ではない**: イベント数をそのまま「X回アクセス」と表現してはならない
- **前面ウィンドウしか記録されない**: Zoom ミーティング中に Slack を見ていれば、その時間は Slack にカウントされる

### データの前処理

分析の前に、以下の前処理を行うこと:

1. **連続する同一ウィンドウイベントのマージ**: 同じ app + title（通知バッジや絵文字の差異は無視）が連続するイベントは1つのセッションとしてマージし、duration を合算する
2. **AFK イベントの重複排除**: 同じ id のイベントが複数ある場合は1つだけ残す

### ミーティング時間の推定

Zoom / Google Meet / Slack ハドル等のミーティングは、前面ウィンドウの記録だけでは実際の参加時間を把握できない。以下のロジックで推定すること:

1. Zoom / Meet / ハドル のイベントが出現する時間帯を特定する
2. その時間帯内で、他アプリ（Slack のチャンネル閲覧、ブラウザ等）を使っていた時間も「ミーティング中に他の画面を見ていた時間」として合算する
3. ミーティングの開始〜終了の時間範囲を推定し、「アプリ別使用時間」とは別に「ミーティング時間（推定）」として報告する

## 分析・出力

取得したデータを前処理した上で分析し、以下のフォーマットで日報を生成する:

```
## 日報 YYYY/MM/DD

### アクティブ時間
- 合計: X時間X分

### ミーティング（推定）
| 時間帯 | 内容 | 推定時間 |
|---|---|---|
| HH:MM〜HH:MM | Zoom ミーティング | X分 |
| HH:MM〜HH:MM | Slack ハドル (#channel) | X分 |
- ミーティング合計: X時間X分

（ミーティングが検出されなかった場合はこのセクションを省略）

### 作業サマリー
（アプリ名・ウィンドウタイトルから推測して、やったことを箇条書き。
職種を問わず、その人が実際に行った作業を正確に記述する。）
- 例: スプレッドシートで売上データの分析
- 例: FigJam で決済フローの仕様検討
- 例: PR レビュー・コードの修正
- 例: Zoom で定例ミーティング参加
- 例: Linear でスプリント計画

### アプリ別使用時間
| アプリ | 時間 |
|---|---|
| ... | ... |

（注: ミーティング中に他アプリを見ていた時間はそのアプリにカウントされるため、
アプリ別時間とミーティング推定時間は重複する。この点を誤解させない表現にすること）

### AI からの一言
（データから読み取れる傾向に基づいた軽いコメント。例: 「今日は分析作業に集中できた日ですね」「ミーティングが多めの日でした」「企画とコーディングを両立した日ですね」など）
```

## 注意
- loginwindow のデータは除外すること
- ウィンドウタイトルから作業内容を推測し、人間が読みやすい形にまとめること
- 使用時間が1分未満のアプリは省略してよい
- 特定の職種（エンジニア等）に偏った表現をしないこと。ユーザーの実際のアプリ利用パターンからその日の役割（開発、企画、分析、マネジメント等）を読み取り、それに合った表現を使う
- 日本語で出力すること
