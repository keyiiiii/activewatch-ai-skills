ActivityWatch API を使って、今週（月曜〜今日）の振り返りレポートを生成してください。

## 環境情報の取得

1. ActivityWatch API のベースURL: `http://localhost:5600/api/0/`
2. まず `buckets/` エンドポイントからバケット一覧を取得し、`aw-watcher-window` と `aw-watcher-afk` で始まるバケット名を動的に特定する
3. 現在時刻から今週の月曜日と今日の日付（JST: +09:00）を算出する

## データ取得

- ウィンドウアクティビティ: `buckets/<window-bucket>/events?start=<monday>T00:00:00%2B09:00&end=<today>T23:59:59%2B09:00&limit=-1`
- AFK データ: `buckets/<afk-bucket>/events?start=<monday>T00:00:00%2B09:00&end=<today>T23:59:59%2B09:00&limit=-1`
- 先週のデータも取得して比較に使う（先週月曜〜先週日曜）

## ActivityWatch データの特性（重要）

ActivityWatch は数秒間隔でアクティブウィンドウをポーリングし、ウィンドウが変わるたびにイベントを記録する。このため以下の特性を理解して分析すること:

- **1イベント ≠ 1アクション**: 同じウィンドウを開いたまま作業していても、タイトルの微変化（通知バッジの増減、🔊アイコンの付け外し等）で複数のイベントが生成される
- **イベント数は「アクセス回数」ではない**: イベント数をそのまま「X回アクセス」と表現してはならない
- **前面ウィンドウしか記録されない**: Zoom ミーティング中に Slack を見ていれば、その時間は Slack にカウントされる

### データの前処理（必須）

すべての分析の前に、以下の前処理を行うこと:

1. **連続する同一ウィンドウイベントのマージ**: 同じ app + title（通知バッジや絵文字の差異は無視）が連続するイベントは1つのセッションとしてマージし、duration を合算する
2. **AFK イベントの重複排除**: 同じ id のイベントが複数ある場合は1つだけ残す
3. **コンテキストスイッチ**: マージ済みイベントで「前のイベントと app が異なる」回数をカウントする。生のイベント数を使ってはならない

## カテゴリ分類ルール

アプリとウィンドウタイトルから以下のカテゴリに分類する。
ブラウザ内の作業はタイトルからサービスを判別し、適切なカテゴリに振り分ける（例: Google スプレッドシート → ドキュメント・分析、Figma → デザイン・企画、GitHub → 開発）。

- **開発**: IDE, ターミナル, Git クライアント、ブラウザ内の GitHub 等
- **ドキュメント・分析**: スプレッドシート, Google Docs, Notion, esa, Confluence, BigQuery 等
- **デザイン・企画**: Figma, FigJam, Miro, Whimsical, Sketch, Adobe 系等
- **コミュニケーション**: Slack, Zoom, Teams, Google Meet, LINE, メール等
- **AI ツール**: Claude, ChatGPT, Gemini, Copilot, Codex 等（ブラウザ内の利用も含む）
- **タスク管理**: Linear, Jira, Asana, Trello 等
- **その他**: 上記に当てはまらないもの

## 注意
- loginwindow のデータは除外すること
- 作業内容はウィンドウタイトルから具体的に推測すること
- 先週データが取得できない場合は「先週比」を省略してよい
- 特定の職種に偏った評価をしないこと。開発が少ない週でも、企画・分析・マネジメントに時間を使っていれば、それは生産的な週として扱う
- 日本語で出力すること
