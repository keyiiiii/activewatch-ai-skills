ActivityWatch API を使って、今日の生産性をスコアリングし、改善提案を行ってください。

## 環境情報の取得

1. ActivityWatch API のベースURL: `http://localhost:5600/api/0/`
2. まず `buckets/` エンドポイントからバケット一覧を取得し、`aw-watcher-window` と `aw-watcher-afk` で始まるバケット名を動的に特定する
3. 現在時刻から今日の日付（JST: +09:00）を特定する

## データ取得

- ウィンドウアクティビティ: `buckets/<window-bucket>/events?start=<today>T00:00:00%2B09:00&end=<today>T23:59:59%2B09:00&limit=-1`
- AFK データ: `buckets/<afk-bucket>/events?start=<today>T00:00:00%2B09:00&end=<today>T23:59:59%2B09:00&limit=-1`

## 分析指標

### 1. 集中スコア（0〜100点）

職種を問わず「深い作業にどれだけ集中できたか」を評価する。以下の要素から算出:

- **ディープワーク比率** — 深い集中を要する作業の合計時間 / アクティブ時間 → 高いほど良い
  - ディープワークの例（職種を問わない）:
    - 開発: IDE, ターミナル, Git クライアント（WebStorm, VS Code, Cursor, Ghostty, iTerm2, Sourcetree 等）
    - 企画・分析: スプレッドシート, ドキュメント作成, Notion, Figma, FigJam 等
    - デザイン: Figma, Sketch, Adobe 系ツール等
  - ウィンドウタイトルからディープワークかどうかを判断する（例: ブラウザでスプレッドシートを編集していればディープワーク、SNS を閲覧していればそうではない）
- **コンテキストスイッチ頻度** — 1時間あたりのアプリ切替回数 → 低いほど良い（20回以下が理想）
- **割り込み回数** — ディープワーク中のアプリ → Slack/メール等への切替回数 → 低いほど良い
- **30秒未満の短いイベント比率** → 低いほど良い

### 2. 時間配分

アプリとウィンドウタイトルから以下のカテゴリに分類して集計する。
ブラウザ内の作業はタイトルからサービスを判別し、適切なカテゴリに振り分ける（例: Google スプレッドシート → ドキュメント・分析、Figma → デザイン、GitHub → 開発）。

- **開発**: IDE, ターミナル, Git クライアント、ブラウザ内の GitHub 等
- **ドキュメント・分析**: スプレッドシート, Google Docs, Notion, esa, Confluence 等
- **デザイン・企画**: Figma, FigJam, Miro, Whimsical 等
- **コミュニケーション**: Slack, Zoom, Teams, Google Meet, LINE, メール等
- **AI ツール**: Claude, ChatGPT, Gemini, Copilot, Codex 等
- **タスク管理**: Linear, Jira, Asana, Trello 等
- **その他**: 上記に当てはまらないもの

### 3. 割り込み分析
- ディープワーク中 → Slack/メール等への切替回数
- 推定集中力ロス時間（切替回数 × 5分として概算）

## 出力フォーマット

```
## Productivity Check - YYYY/MM/DD HH:MM

### 今日の作業傾向
（データから読み取れるその日の主な役割を1行で。例: 「企画・分析が中心の日」「開発とコミュニケーションが半々の日」「ミーティング多めのマネジメント日」）

### 集中スコア: XX/100 点
（スコアの根拠を1〜2行で。ディープワークの内容を職種に合わせて言及する）

### 時間配分
（実際に検出されたカテゴリのみ表示。ゼロのカテゴリは省略）
開発           ██████░░░░ 30%  1.5h
ドキュメント・分析 ████░░░░░░ 20%  1.0h
コミュニケーション ████████░░ 40%  2.0h
AI ツール       ██░░░░░░░░ 10%  0.5h

### 改善サジェスト
1. （最も効果が大きい改善ポイント）
2. （具体的なアクション提案）
3. （データに基づいた気づき）

### 効率化ヒント
（反復的な作業パターンを検出した場合、自動化や効率化の具体的な提案を行う。
例: 「同じスプレッドシートにX回アクセスしています。ダッシュボード化すると確認コストを減らせます」
例: 「PR確認をX回手動で行っています。通知をフィルタリングすると削減できます」
例: 「ミーティングの前後にドキュメント作業が分断されています。ミーティングをまとめてブロック化すると集中時間を確保しやすくなります」）
```

## 注意
- loginwindow のデータは除外すること
- スコアは厳しめに。80点以上は本当に集中できた日のみ
- 改善提案はデータに基づいた具体的なものにすること（一般論ではなく）
- 「コーディングが少ない＝生産性が低い」ではない。企画・分析・ドキュメント作業も立派なディープワークとして評価する
- 褒めるべきところは褒める
- 日本語で出力すること
